Build a complete automated NH-PKing combat tool for the Orion private server.

PURPOSE

The tool should automatically control NH PvP combat against the player's current opponent.

It should operate as a tick-aware combat state machine capable of:

- Detecting and maintaining the current PvP opponent.
- Reading the opponent's overhead protection prayer.
- Automatically choosing an appropriate combat style.
- Switching between user-configured Melee, Ranged and Magic gear.
- Automatically switching offensive prayers.
- Automatically switching defensive protection prayers based on the opponent's current attack style/gear.
- Casting Ice Barrage when appropriate.
- Performing ranged attacks when appropriate.
- Performing melee attacks when appropriate.
- Handling special attacks according to configurable rules.
- Switching gear and attacking within one game tick when possible.
- Detecting freezes and freeze timers.
- Detecting whether the local player or opponent can move.
- Tracking attack cooldowns.
- Avoiding redundant gear/prayer/spell clicks.
- Maintaining the same target throughout an action sequence.
- Providing detailed debugging/timing telemetry.

Do NOT build the program as one giant sequence of sleeps and clicks.

Use a modular event-driven finite-state architecture driven primarily by game ticks and client state.

Prefer item IDs rather than names.

Example:

5. Equip those items.
6. Avoid redundant clicks.
7. Abort cleanly if required equipment is unavailable.

7. ONE-TICK MAGIC BARRAGE
==================================================

Critical behavior:

IF opponent switches into PROTECT_FROM_MISSILES:

    lock current target

    determine missing MAGIC_GEAR items

    equip MAGIC_GEAR

    enable configured offensive magic prayer

    select ICE_BARRAGE

    cast on SAME target

Attempt to complete the gear + prayer + spell + target input sequence inside the current actionable tick window.

Sequence:

DETECT PROTECT FROM MISSILES
        ->
LOCK TARGET
        ->
MAGIC GEAR
        ->
MAGIC OFFENSIVE PRAYER
        ->
ICE BARRAGE
        ->
TARGET

Never cast on a newly discovered target midway through the sequence.

==================================================
8. RANGED COUNTER
==================================================

IF opponent protects from Magic:

    consider switching to RANGED_GEAR

Sequence:

lockTarget
switchGear(RANGED_GEAR)
activate configured ranged offensive prayer
attack locked target

Avoid attacking before required equipment actions have been submitted.

==================================================
9. MELEE COUNTER
==================================================

IF opponent protects from Magic and melee is strategically preferable:

    switchGear(MELEE_GEAR)
    activate configured melee offensive prayer
    attack target

Only select melee when:

target distance permits melee
OR
movement/pathing permits reaching target
OR
configured strategy explicitly wants melee pressure.

23. SAFETY / CONSISTENCY RULES
==================================================

Never:

attack an unintended target
switch to equipment that isn't configured
spam the same prayer
spam Ice Barrage selection
spam attack interactions
continue a sequence against a dead/invalid target
continue using stale target information
execute a queued attack whose preconditions are no longer valid

Every queued action should verify its preconditions immediately before execution.

==================================================
FINAL TARGET BEHAVIOR
==================================================

The finished tool should behave as a tick-aware NH PvP controller.

Example:

Enemy equips ranged setup
    -> protect from ranged

Enemy switches protection to missiles
    -> magic gear
    -> magic offensive prayer
    -> Ice Barrage
    -> same opponent

Enemy switches protection to magic
    -> choose ranged/melee
    -> appropriate gear
    -> appropriate offensive prayer
    -> attack

Enemy prepares magic attack
    -> protect from magic

Enemy prepares ranged attack
    -> protect from missiles

Enemy prepares melee attack
    -> protect from melee

Opponent becomes unfrozen / freeze nearly expires
    -> increase Barrage/re-freeze priority

Opponent reaches configured KO HP
    -> evaluate special-attack opportunity

All actions must be based on current combat state, synchronized with game ticks,
and use the minimum necessary gear/prayer/interface interactions.

Prioritize deterministic state handling, target integrity, tick synchronization,
and detailed telemetry over random sleeps or blind coordinate clicking.

Start by examining the existing Orion project and tell me:
1. What APIs/hooks already exist.
2. Which modules/files should be created.
3. Which existing files need modification.
4. How game ticks, actors, equipment, prayers, inventory interactions and spell
   casting are exposed by Orion.

Then implement the system phase-by-phase, compiling/testing after each phase
instead of attempting the entire system in one unverified code dump.

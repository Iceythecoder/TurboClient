# Gauntlet validation record

## Verified by automated tests

- The Gauntlet launcher uses a distinct mode, process mutex, release pointer, session
  record, host JAR, feature JAR, and profile directory.
- The feature compiles against the unchanged local Orion client and Java 11 runtime.
- Unknown or OSRS-reference identifiers cannot arm control.
- Auto-detect selects Regular only from a non-corrupted observed fixture; explicit
  modes remain available when the corrupted discriminator is unknown.
- Immediate floor/tornado danger outranks the active state-machine objective.
- The run-local graph finds a path through newly observed room connections.
- Action submission cannot confirm itself; confirmation requires an observed
  postcondition. Retry is bounded and old run generations are cancelled.
- Resource reservation prevents double-spending and reports plan shortages.
- Duplicate projectile movement and stomp events do not corrupt Hunllef's observed
  four-attack style cycle; six off-prayer player attacks are tracked separately.
- The tile-time planner rejects future-active intermediate tiles and returns no route
  rather than guessing when every route is sealed.
- F9 and host reload call the feature's stop/close lifecycle.
- Diagnostic capture is bounded and does not save automatically.

## Requires live Orion evidence

- Regular and Corrupted instance discriminators.
- Start, preparation, Hunllef, reward, and exit room/object identifiers.
- Resource nodes, tools, singing bowl/range/pestle interactions, recipes and quantities.
- Food, potion, armor, weapon, perfected-component and shard item identifiers.
- Demi-boss NPCs, drop confirmation, duplicate-component conversion, and weapon choice.
- Hunllef ranged/magic projectiles, overhead protection, stomp range, attack cadence,
  floor warning/active graphics, tornadoes, blocked tiles, prayer disable and death.
- Reward chest acknowledgement and exit acknowledgement.

## Acceptance status

The independent feature, observer, state model, persistence boundary, launcher, build,
and safe signal gate are implemented and tested. A full autonomous regular/corrupted
completion is **not yet claimed** because the Orion-specific mappings and live action
acknowledgements above have not been captured. The diagnostic workflow exists to
collect precisely those facts without fabricating them.
